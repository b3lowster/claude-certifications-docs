# Model options and reasoning modes
# Варианты моделей и режимы рассуждения

## The Claude model family
## Семейство моделей Claude

Claude is a family of models that currently spans four tiers: Fable, Opus, Sonnet, and Haiku. Each model represents a different tradeoff across cost, latency, and capability. Sonnet is the balanced default for most production workloads. Haiku is built for speed and cost efficiency on tasks that fit its capability envelope. Opus handles demanding work above the Sonnet envelope, and Fable is the most capable tier, built for the most demanding reasoning, coding, and agentic work where maximum intelligence is the priority. The practical default is to start with Sonnet, move up a tier only when an eval shows the current tier missing your quality bar, and move down to Haiku only when an eval shows the quality drop is acceptable for the task. Confirm the current model lineup and identifiers against platform.claude.com/docs at build time, since the Claude family is evolving.

> Claude — это семейство моделей, которое сейчас включает четыре уровня (tiers): Fable, Opus, Sonnet и Haiku. Каждая модель представляет собой свой компромисс между стоимостью, задержкой (latency) и возможностями. Sonnet — сбалансированный вариант по умолчанию для большинства продакшен-нагрузок. Haiku создана для скорости и экономичности на задачах, которые укладываются в границы её возможностей. Opus справляется с требовательными задачами, выходящими за границы возможностей Sonnet, а Fable — самый мощный уровень, созданный для наиболее сложных задач рассуждения, программирования и агентной работы, где приоритетом является максимальный интеллект. Практическое правило по умолчанию: начинайте с Sonnet, переходите на уровень выше, только когда eval показывает, что текущий уровень не дотягивает до вашей планки качества, и переходите на Haiku, только когда eval показывает, что падение качества допустимо для задачи. Проверяйте актуальную линейку моделей и их идентификаторы на platform.claude.com/docs на этапе разработки, поскольку семейство Claude развивается.

## Reasoning modes are a separate setting from model choice
## Режимы рассуждения — отдельная настройка, не зависящая от выбора модели

Choosing which model to run is one decision. Whether the model reasons before answering is a separate decision you make per call. On current models the reasoning mode is adaptive thinking: the model decides when and how much to think, and you tune depth with an effort setting rather than a fixed token budget (the older budget_tokens control is deprecated and, on the newest model generations, returns a 400 error). Thinking content is omitted from responses by default on the newest models. Request summarized display when you need to show it. Reasoning earns its cost on hard, multi-step problems and is wasted on lookups and classification. The key point for this module is that the two levers compose: model choice picks the family member, while the reasoning mode is configured per request. Per-model defaults differ (some of the newest models think adaptively by default or always), so confirm the current thinking defaults for your model at build time.

> Выбор модели для запуска — это одно решение. Будет ли модель рассуждать перед ответом — отдельное решение, которое принимается для каждого вызова. На текущих моделях режим рассуждения — это адаптивное мышление (adaptive thinking): модель сама решает, когда и сколько думать, а вы настраиваете глубину с помощью параметра effort, а не фиксированного бюджета токенов (старый параметр `budget_tokens` устарел (deprecated) и на новейших поколениях моделей возвращает ошибку 400). На новейших моделях содержимое размышлений (thinking) по умолчанию не включается в ответы. Запросите отображение в виде краткого изложения (summarized display), если вам нужно его показать. Рассуждение окупает свою стоимость на сложных многошаговых задачах и тратится впустую на поиск справочной информации (lookups) и классификацию. Ключевой момент этого модуля в том, что два рычага сочетаются: выбор модели определяет конкретного представителя семейства, а режим рассуждения настраивается для каждого запроса. Значения по умолчанию различаются у разных моделей (некоторые из новейших моделей по умолчанию или всегда думают адаптивно), поэтому проверяйте актуальные настройки thinking по умолчанию для вашей модели на этапе разработки.

## How the two work together
## Как они работают вместе

Because model choice and reasoning mode are independent, each can be set separately. A capable model with reasoning off is fast and direct, while a smaller model with reasoning on spends more tokens to think. The most demanding tasks pair a capable model with a higher effort setting. Module 2 teaches the mechanics of enabling reasoning and handling the thinking blocks it returns. The decision of which model to run, weighed against cost, latency, and quality, is taken up in Module 4.

> Поскольку выбор модели и режим рассуждения независимы, каждый из них можно задавать отдельно. Мощная модель с выключенным рассуждением работает быстро и отвечает напрямую, тогда как модель поменьше с включённым рассуждением тратит больше токенов на размышления. Для самых требовательных задач мощную модель сочетают с более высоким значением effort. В Модуле 2 разбирается, как включать рассуждение и обрабатывать возвращаемые им блоки thinking. Решение о том, какую модель запускать, с учётом стоимости, задержки и качества, рассматривается в Модуле 4.
